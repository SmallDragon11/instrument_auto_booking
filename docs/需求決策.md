# 已確認的需求決策

| # | 議題 | 決策 |
|---|---|---|
| 1 | 下週的工作表尚未建立 | 直接回報失敗，不自動建立工作表 |
| 2 | 時段衝突 | 使用者指定的一段連續時段只要有任一格已被佔用，整段跳過，改試下一個優先序的選項；全部處理完後向使用者回報預約結果。各筆彼此獨立（全部都想要），優先序只決定搶的先後 |
| 2a | 自己的時段重疊 | 允許，視為互為備案；只有高順位實際寫入成功，重疊的低順位才跳過 |
| 2b | 氣體不在圖例 | 改用使用者選擇時的色碼寫入，結果附警告（不算失敗） |
| 3 | 溫度 | 暫不填寫 |
| 4 | Google 授權 | 使用者以個人 Google 帳號 OAuth 登入（不使用服務帳戶） |
| 5 | 設定頁 | 使用者人名、預約填寫時間（預設每週五 13:00）在 App 的 Setting 頁設定 |
| 6 | 寫入方式 | 預約表是 Google 雲端硬碟上的 `.xlsx`（Office 編輯模式），Sheets API 無法使用。採**瀏覽器自動化**（Playwright 操作使用者已登入的瀏覽器），不更動實驗室現行檔案與流程 |
| 7 | 使用者 | 實際使用者不是開發者，App 必須能直接雙擊執行，設定一次後即可使用 |
